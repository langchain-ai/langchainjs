Upgrading from adapter 1.x: `new MCPAdapter({ servers })` is the canonical client API, while `MultiServerMCPClient` and server-map configurations still work with the class alias deprecated. `getTools()` becomes `listTools()`. Read configuration through `adapter.config.servers` for any constructor form, typed as `ResolvedMCPAdapterConfig`; the getter no longer exposes `mcpServers`. Connections negotiate automatically, `mode: "legacy"` enables legacy callbacks and connection options, and `mode: "modern"` prevents negotiation and SSE fallback. `SSEConnection` accepts only legacy SSE — use `StreamableHTTPConnection` for HTTP or `Connection` for any transport. Stdio `encoding` is unsupported; retry counts must be nonnegative integers and delays nonnegative.

Upgrade to Zod 4. Configuration rejects conflicting options, unknown output-handling keys, incompatible fields, and empty server maps with Zod errors; hook argument overrides must be objects. Snapshots preserve notification callbacks, tool hooks, and OAuth provider identity, and connection-error handlers keep native Zod function validation. Tool schemas preserve the original server JSON Schema through the official MCP core schemas and SDK validator: automatic simplification is gone, model-specific overrides stay separate from post-hook argument validation, and loader options reject invalid values before discovery.

Hook `state` is typed `unknown` rather than an object record; the runtime value is unchanged, so narrow it before accessing properties. `useStandardContentBlocks` is gone — tool content is always standard LangChain blocks, so image and audio consumers read `data` and `mimeType`. Artifact-routed blocks keep their MCP format, including through `afterToolCall`, and resource reads stay explicit. Resource types derive from the MCP SDK and `readResource()` preserves SDK content metadata, so narrow with `"text" in content` or `"blob" in content`. Notification and progress callbacks move into each server configuration, where `onInitialized` and explicit SSE fallback require legacy mode. `onRootsListChanged` is removed: roots notifications come from clients, so that server observer never implemented roots support. Pass workspace paths through tool parameters, resource URIs, or server configuration. Global LangChain hooks, naming, output policies, and load-error handling remain adapter options.

Branded `ToolException` and `MCPClientError` require `@langchain/core ^1.2.6`. Both are exported and preserve original causes: tool failures keep MCP error responses in `result`, SDK argument-validation issues become Zod4 errors, and messages keep the original error text without custom Zod formatting, with issues, paths, and stacks in `cause`. Narrow with `isToolException()` or the classes' `isInstance()` methods, since name-only lookalikes no longer match across module copies.
